# 数据导出设计

> 本文描述导出类型目录、筛选范围模型、列规范与权限约束。
> 改动本文时请同步更新 `Design/english/12-DataExport.md`。
> 相关文档：权限与数据范围模型见 `10-RolesAndPermissions.md`；导入见 `11-DataImport.md`。

---

## 1. 这份设计要回答的问题

导出是学生数据离开本系统的出口。一份 CSV 一旦生成，就不再受本系统的任何权限约束——
它会被转发、被留在共享盘上、被打开在一台没人管的电脑上。

因此导出设计要同时成立三件事：

1. **只导出该导出的行**——由权限与数据范围两个轴共同决定；
2. **导出的内容对收件人是可读的**——而不是一堆只有本系统能解释的内部标识；
3. **每一份导出都能说清自己是什么**——标题、说明、筛选条件，在文件之外也要能讲明白。

---

## 2. 通用原则

### 2.1 不导出数据库标识

`id`、`studentId`、`projectId`、`reviewerId`、`gradeId` 这类标识**一律不出现在导出文件中**。

理由不是冗余，而是它们对收件人没有意义：契约中标识是不透明的服务端生成串，
不携带任何可解读信息，拿到手也无法与任何东西对照——它是通往一个对方并不拥有的
数据库的连接键。

需要标识一名学生时，用**学号**；需要标识一个项目时，用**项目名称**。

分页游标仍然使用 `id`（键集分页，避免深翻页退化为全表扫描），但它只存在于查询内部，
不写入文件。

### 2.2 凡出现学生姓名，必同时给出学号

姓名不是标识。同名在一所学校里是常态，本系统的测试数据里就有多组同名。
任何按学生汇总、核对或合并的用途，只有姓名都是不可靠的。

**因此"学生姓名"列永远与"学号"列成对出现**，学号在前。

### 2.3 首列是行号，不是 ID

每份导出的第一列是从 1 开始的行序号，列名为 `No.`。

它**不叫 `ID`**：这份设计刚刚把数据库标识从导出中移除，再用 `ID` 命名一个行号，
会让读者以为它是某种系统编号并试图引用它。行号只在这一个文件里有意义，
重新筛选一次就会变。

### 2.4 空值就是空单元格

某列在某行没有值时，写**空单元格**——不写 `null`、不写 `N/A`、不写 `-`。

这条规则来自一次真实缺陷：未审核通过的记录没有入账金额，而代码把 `null` 直接转成了
字符串，于是文件里出现了字面量 `null`。电子表格会把它当成文本，求和、筛选与排序
全部受影响。

### 2.5 单位与格式

| 类型 | 规范 |
| :--- | :--- |
| 时长 | 整数分钟，列名含 `Minutes`；汇总值用小时，列名含 `Hours` |
| 时间币 | 以**枚**为单位（`1`、`1.5`），不是内部存储的百分之一枚 |
| 比率 | 百分比，保留两位小数，形如 `85.71%` |
| 日期 | `YYYY-MM-DD` |
| 时间戳 | `YYYY-MM-DD HH:MM` |
| 状态/角色 | 稳定的英文可读文案（`Approved`），不是数据库枚举（`APPROVED`） |

### 2.6 列名不做多语言，标题与说明要做

**数据列名固定英文**，不随界面语言变化。导出文件常被转交给第三方工具或长期归档，
列名随语言漂移会让下游处理逻辑失效。

**导出卡片的标题与说明必须支持中英文**，它们是给使用者读的。

### 2.7 CSV 安全

以 `=`、`+`、`-`、`@`、制表符、回车开头的单元格会被电子表格当作公式执行。
学生姓名与描述是用户可控内容，因此所有字段在写入前统一做公式注入中和处理。
这条已在现有实现中成立，本设计不得削弱它。

## 3. 界面形态

- 导出与导入是**两个独立标签页**；无权限者**不显示**对应标签页。
- 导出页是**单列卡片列表**，一种导出一张卡片。
- 每张卡片包含：**标题**、**说明**、一个**展开**按钮；展开后显示该导出的筛选器与
  「导出…」按钮。
- **用户无权访问的导出类型，其卡片不显示**，而不是显示为禁用。
- 导出是异步任务：点击后生成任务，完成后通过一次性下载令牌取回文件。

## 4. 筛选范围模型

### 4.1 三个筛选维度

| 筛选器 | 取值 | 默认值 |
| :--- | :--- | :--- |
| 学年 | 全部学年 / 具体某一学年 | **全部学年**（§4.2 的例外除外） |
| 年级 | 全部年级 / 具体年级 | **全部年级** |
| 班级 | 全部班级 / 具体班级 | **全部班级** |

**所有筛选器默认为「全部…」**，而不是默认为某个具体值。默认一个具体值，
意味着用户在不改动任何筛选器时拿到的是一份被悄悄裁剪过的数据。

### 4.2 唯一的例外：学生达标情况

「学生达标情况」的学年筛选**默认为当前学年**，因为它的「年度要求」与「达标率」
按定义是**一个学年之内**的度量。跨全部学年求达标率没有意义——分母不存在。

### 4.3 筛选器与数据范围是两回事

筛选器是用户**主动收窄**的选择；数据范围是系统**强制施加**的上限。

一位绑定九年级的教师，即使把年级筛选器选成「全部年级」，得到的仍然只有九年级。
筛选器永远不能扩大范围，只能在范围内进一步收窄。

**教师的年级筛选器只列出其绑定的年级**，不列出他看不到的年级——列出一个选了也
没有结果的选项，只会让人以为系统出错了。

### 4.4 导出一律按**学生**取范围

年级被冗余写在服务记录、申诉、活动提案等表上，系统的范围过滤在这些界面上读的是
**记录自身的年级快照**，而不是学生的现时年级（`10-RolesAndPermissions.md` §7.2.1）。

**导出不沿用这套过滤。** 一份导出是一张关于**学生**的报表：

1. 先按数据范围确定**学生集合**（教师取其绑定年级的现时学生，SDC 管理员取全部）；
2. 再取这些学生在所选学年内的数据，**不论那些记录当时挂在哪个年级**。

若沿用快照过滤，一名刚升上九年级的学生，其八年级时期的时长会在九年级教师的导出里
凭空消失，而那名学生的行仍在表中——同一张表里，学生在、他的数据不在。
这不是范围收窄，这是一张自相矛盾的报表。

审核队列等**以记录为主体**的操作界面不受此影响，仍按快照过滤：在那里"发生在我年级
里的事"才是正确口径。

## 5. 学年、年级与毕业生

### 5.1 年级是按学年推导的，不是查出来的

本系统的 `student.grade_id` 是**现时**字段：它记录学生今天在哪个年级，
数据库中不保存历史名册。因此"2023-2024 学年这名学生在几年级"无法直接查询。

推导依赖学段模型（`13-AnnualRollover.md` §2）：学校分两个学段，
**第一学段为六至八年级（3 年），第二学段为九至十二年级（4 年）**，
学生从六年级或九年级入学。

入学年级本身也由推导得出，结果必为 6 或 9：

```
入学年级   = 当前年级 − (当前学年起始年 − 入学学年起始年)
当年年级   = 入学年级 + (目标学年起始年 − 入学学年起始年)
```

某学生于 2026-2027 学年从六年级入学（第一学段）：

| 导出所选学年 | 年级列显示 |
| :--- | :--- |
| 2026-2027 | 六年级 |
| 2027-2028 | 七年级 |
| 2028-2029 | 八年级 |
| 2029-2030 及以后 | `Graduated (2029)` |

同一条规则还回答了"这名学生当年在不在校"：

```
在校（学年起始年 Y）  ⇔  入学学年起始年 ≤ Y ≤ 毕业年 − 1
```

不在该学年在校的学生**不出现在该学年的导出中**。

### 5.2 一个人可能是两条学生记录

八年级升九年级在本系统中是**毕业加重新入学**，不是升级
（`13-AnnualRollover.md` §2.1）：学号重新分配，时间币与服务时长从 0 开始。

因此**任何一份导出都不会呈现某人从六年级到十二年级的连续历史**——
那是两条学生记录、两个学号，分属两个学段。这不是缺陷，而是那条设计的直接结果：
跨学段的记录迁移因学号变更、班级重命名与学生流失而不可靠，系统明确不做。

需要一个人的完整轨迹时，只能由人工按姓名与年份比对两条记录，系统不代为关联。

### 5.2.1 这条推导的边界

推导假设**没有留级与跳级**，因为系统不建模这两件事。一旦确实出现留级，
该学生的历史年级会偏移一年。`13-AnnualRollover.md` §5 的一致性检查会把这类学生
报为不一致，这是发现它们的唯一信号。

### 5.3 学年筛选为「全部学年」时

没有单一学年可供推导，因此**年级列显示现时年级**；已毕业学生显示
`Graduated (YYYY)`。

### 5.4 `GRADUATED` 状态由学年流程写入

`StudentStatus` 枚举含 `GRADUATED`，而在 `13-AnnualRollover.md` 定义的学年流程
落地之前，**没有任何代码写入它**——只有 `ACTIVE` 与 `INACTIVE` 被真正使用。

该流程落地后，八年级与十二年级学生在每年 9 月 1 日被置为 `GRADUATED`，
其登录账号同时停用。

导出中的"已毕业"**始终按毕业年推导**（§5.1），不读状态字段。这样写是刻意的：
推导在学年流程尚未实现时也成立，在某一年漏跑时同样成立，而读状态字段两种情况下
都会给出错误答案。

## 6. 导出类型目录

共七种。每种给出标题、说明、所需权限、筛选器与数据列。

> 原有的 `participation`（各年级参与率）与 `serviceHours`（月度时长趋势）两种导出
> **退役**：前者已被「学生达标情况」覆盖且更细，后者是一条 12 个点的趋势线，
> 在屏幕上比在 CSV 里更有用。两者的权限行按 `10-RolesAndPermissions.md` §5.2
> 保留并标注退役。

---

- **说明**：学生提交的服务记录明细，含各审核状态与已入账时间币。
- **权限**：`exports.serviceRecords`
- **筛选器**：学年、年级、班级

| # | 列名 | 说明 |
| ---: | :--- | :--- |
| 1 | `No.` | 行号 |
| 2 | `Student Number` | |
| 3 | `Student Name` | |
| 4 | `Grade` | 按所选学年推导 |
| 5 | `Class` | |
| 6 | `Service Date` | 服务日期 |
| 7 | `Service Category` | 服务类别 |
| 8 | `Project / Organisation` | 项目来源填项目名；自主来源填组织名 |
| 9 | `Duration Minutes` | 整数分钟 |
| 10 | `Credited Coins` | **仅审核通过的行有值；其余为空单元格** |
| 11 | `Status` | `Approved` / `Pending Review` / `Returned` / `Rejected` |

**状态映射与草稿的处理**：

| 系统状态 | 导出显示 |
| :--- | :--- |
| `APPROVED` | `Approved` |
| `SUBMITTED`、`UNDER_REVIEW` | `Pending Review` |
| `RETURNED` | `Returned` |
| `REJECTED` | `Rejected` |
| `DRAFT` | **不导出** |

草稿是学生尚未提交的私人草稿，不是向学校做出的任何声明，因此不进入任何导出。

> **注意**：本导出包含全部已提交状态，是一份提交明细而非入账明细。因此
> `Credited Coins` 列必然存在空单元格——这是正确的（未通过审核即无入账），
> 但意味着这一列不能被直接求和用作"学校总入账"。需要入账口径时，
> 请按 `Status = Approved` 先行筛选。

### 6.3 学生达标情况（`studentCompletion`）

- **标题**：学生达标情况
- **说明**：按学年统计每名学生的服务时长、已获时间币与年度达标进度。
- **权限**：`exports.studentCompletion`
- **筛选器**：学年（**默认当前学年**，§4.2）、年级、班级

| # | 列名 | 说明 |
| ---: | :--- | :--- |
| 1 | `No.` | |
| 2 | `Student Number` | |
| 3 | `Student Name` | |
| 4 | `Grade` | |
| 5 | `Class` | |
| 6 | `Projects Participated` | 该学年内有已通过记录的项目数 |
| 7 | `Approved Service Hours` | 该学年内已通过的服务小时数 |
| 8 | `Credited Coins` | 该学年内已入账时间币 |
| 9 | `Annual Required Hours` | 该生学段的年度要求（初中 25h，高中 75h） |
| 10 | `Gap Hours` | `max(0, 年度要求 − 已通过小时)` |
| 11 | `Completion Rate` | `已通过小时 / 年度要求`，两位小数百分比 |

> 第 7 列与第 8 列在当前规则下数值相同（1 小时 = 1 枚时间币），但**不是冗余**：
> 折算比例由规则版本决定，且每条记录按其服务日期当时的规则折算。若将来发布了
> 不同折算比例的规则版本，两列就会分开。`Gap Hours` 是给教师用的可执行数字——
> 「还差几小时」比「达标率 67%」更直接。

| 11 | `End Date` | |
| 12 | `Recognized Minutes` | 项目认定的服务时长 |

> **较草稿的调整**：删去 `Project Description`——它是整段文字，放进 CSV 会破坏

> 「项目时长」改名为 `Recognized Minutes` 并只保留一列：原稿中它与起止日期并存，

> 提交质量，不受名额是否虚高影响。

### 6.7 审核历史（`reviewHistory`）

- **标题**：审核历史
- **说明**：逐条审核决定的明细，含退回与驳回的原因。
- **权限**：`exports.reviewHistory`
- **筛选器**：学年、审核人

## 8. 刻意不做的事

- **不做自定义列。** 让用户自选列，意味着每一份导出的含义都要靠文件本身自证，
  而 CSV 不携带这种说明。
- **不做定时导出。** 导出是一次取走数据的行为，应当有人在那一刻对它负责。
- **不做导出结果的服务端长期留存。** 文件生成后经一次性令牌取回，不作为可反复
  下载的资产长期存放。
- **不在导出中提供联系方式。** 学生邮箱与监护人信息不属于任何一份导出——
  数据最小化的要求在出口处最应当被坚持。
